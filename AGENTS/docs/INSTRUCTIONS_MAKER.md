# Instructions Maker

Use only for evaluating or changing model-facing instructions under [AGENTS](../../AGENTS.md), not ordinary production that follows them.

## Establish the decision

Identify intended behavior, audience, authorization and the actual instruction chain. Separate organizational choices from host facts. Verify changing host/loading claims with current official documentation; a link or descriptor does not prove loading or priority.

## Evaluate an existing system

Trace representative requests through the owners an agent can encounter. Find omissions, conflicting procedures and duplicated responsibility. Preserve useful medium requirements and evidence limits. Review-only scope does not authorize edits.

## Abstract the behavior before drafting

Identify the governing condition behind an example. Check covered and excluded cases and existing coverage. Prefer correcting the current owner; do not turn one incident into a broad workflow or standing restriction without need.

## Choose the instruction surface

Keep complete local methods, studio requirements and brand decisions in this repository. The central project home owns registration, routing and workspace continuity. Correct the lowest responsible owner; do not create another manifest, home or parallel knowledge tree. Retain actual host priority and explicit user direction.

## Keep the system self-contained

Each standing rule's condition, behavior, scope and material exceptions must be available through canonical routes. Temporary records, memory, external citations and unavailable installations cannot supply missing operative policy. State conditions directly without incidental release names or adoption history.

## Draft and validate

Write the smallest sufficient correction. Read the final chain and exercise realistic positive and negative cases; run the [documentation and regression checks](../../ENGINEERING.md#documentation-checks). Distinguish static routing, controlled fixtures, observed host behavior and production acceptance.
