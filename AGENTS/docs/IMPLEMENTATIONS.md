# Implementations

Use for authorized implementation and corrections under [AGENTS](../../AGENTS.md). Studio [PRODUCTION](../../PRODUCTION.md) owns workspace, retention and delivery requirements.

## Execute and correct

Read the selected task and affected owners. Keep settled direction and unrelated changes intact. Identify the responsible layer and affected dependencies; change coupled producers, consumers and instructions together. Preserve compatible public contracts. Diagnose failures before changing policy or debt baselines. Fix at the responsible layer and repeat affected checks plus configured gates.

## Review and verification

Apply [VERIFICATIONS](VERIFICATIONS.md) to actual results. For software tools, inspect callers and tests and add focused regressions for changed decisions/failure boundaries. Use the project's language and existing stack. Do not install a replacement environment to conceal missing production prerequisites.

## Implementation record

Use the single task record and baseline specified by [production records](../../PRODUCTION.md#revisions-and-records). Implementation source stays in its repository. Move lasting verified decisions into their existing owners incrementally; supporting evidence does not become a competing current-state record.

## Stops, completion, and handoff

Honor the requested outcome and explicit review stops. Finish applicable checks, assess the actual diff/output and reconcile the record. Report checks and limits, unresolved requirements and next action. Completion does not trigger a package, archive, task migration or cleanup.

## Resumption

Read the exact selected task.md, its necessary references and current editing entry point; check relevant drift and continue its next action. Never select the newest task implicitly, recreate a task per revision or relocate a legacy layout to resume it.
