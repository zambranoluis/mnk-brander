# mnk-brander studio

A multidisciplinary workspace for developing brands and products from an undefined idea through strategy, identity, design, prototypes, production and handoff. Digital builds are included; physical construction is excluded. Executable websites, native apps and services retain dedicated repositories. This repository owns the complete studio requirements, brand decisions, production packages, tools and authoritative assets. The selected central project home owns registration, routing and workspace continuity.

## Entry and ownership

For independent work, enter through the source repository's [working agreement](AGENTS.md) and local methods. For base-led work, resolve project `mnk-brander` or alias `brander` through the selected base's helper, select an exact task with `--task` for recorded work, and use that base's shared methods. Both entries use these repository-owned requirements and one task record/baseline. Standing guidance is complete in this repository; the task/session supplies the selected central workspace location.

The central home's existing descriptor binds this repository as `studio` and declares the maintained context. Repository `docs-owners.json` checks local guidance by default; explicit legacy external-owner and method modes remain supported. Source and nested instructions still apply. Links do not prove host loading or grant writes.

## Independent brands and production truth

Monolith's established foundation and unresolved identity remain in its brand owner. OpenJM's retained source owners are `productions/openjm/openjm-PRODUCT.md` and `productions/openjm/openjm-DESIGN.md`; explicitly read both for OpenJM creative work. They describe that product, never studio-wide standards or proof of deployed capability. They remain source-owned and preserved. Their original implementation-layer link is unavailable in this repository; use the owning product project for executable facts, as explained in [ENGINEERING](ENGINEERING.md#unavailable-production-prerequisites).

Consult related product context only for authoritative facts needed by a task. Resolve the registered product separately; source selection or related knowledge never authorizes edits. This studio declares no standing related-project dependency. Studio proposals, synthetic fixtures and static concepts do not alter those products.

New task records use the selected central project workspace at `<workspace>/<task-name>/task.md` under [production records](PRODUCTION.md#revisions-and-records). Existing histories, production packages and prior outputs remain where found. Do not infer a current editing target or approval from the newest file. [PRODUCTION](PRODUCTION.md) owns handoff and review states.
